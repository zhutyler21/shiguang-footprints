# 拾光足迹 · 照片打卡网页（本地）

## 当前状态

MVP 源码已实现：React + Vite 前端、Express 服务端、SQLite 数据库和本地照片存储。无需登录，仅监听本机。用户提供的高德 Key 和安全密钥已配置在本地 .env。真实高德地图加载、GPS 转换、手动选点、保存、历史联动和删除已通过合成照片端到端验收。

## 安装与启动

需要 Node.js 22.12 或更高版本。终端进入本项目目录后执行：

```bash
npm ci
# .env 不存在时执行；已有配置请直接编辑，不要覆盖
cp .env.example .env
npm run dev
```

打开 **http://127.0.0.1:5173/**。开发模式同时运行前端（5173）和后端（默认 3001）；修改代码会自动刷新或重启。

构建后的使用方式：

```bash
npm run build
npm start
```

打开 **http://127.0.0.1:3001/**。该地址由 Express 提供完整前后端功能。`dist/index.html` 是构建产物，需要本地服务端，不能直接双击当作独立应用使用。改动前端后须重新构建。

停止服务：在启动终端按 `Ctrl+C`。数据不会因停止而删除。端口占用时停止旧服务；后端可通过 `.env` 的 `PORT` 修改，前端默认严格使用 5173。

## 高德地图配置

1. 在高德开放平台创建 **Web 端（JS API）** Key，取得同一 Key 配套的安全密钥。
2. 在本地 `.env` 填写 `AMAP_KEY`、`AMAP_SECURITY_CODE`；勿添加 `VITE_` 前缀，勿将安全密钥写入前端。
3. 重新启动服务；开发版刷新 5173 页面，构建版访问 3001。
4. 如启用访问限制，将本机访问域名按控制台要求配置。检查网络、Key 类型、配套安全密钥以及使用权限。

前端仅从 `/api/config` 取得浏览器加载需要的 Key。`window._AMapSecurityConfig.serviceHost` 指向同源 `/_AMapService`，服务端固定转发到高德官方域名并注入安全密钥，不接受任意代理目标。配置缺失或加载失败时显示提示与重试入口；地图未就绪时禁止确认和保存。

详细配置入口：`/api/setup-guide`。实现参考[高德官方安全代理说明](https://lbs.amap.com/api/javascript-api-v2/guide/abc/jscode)和[官方 GPS 坐标转换说明](https://lbs.amap.com/api/javascript-api-v2/guide/transform/convertfrom)。

## 界面文案与配色

首页标题为“把走过的风景，写成时光的诗。”，表达照片与足迹承载回忆的主题。

采用柔和蓝色系的马卡龙配色：冰蓝白背景、雾蓝色主按钮、浅天蓝装饰与蓝色地图标记、深蓝灰文字。配置说明页和网站图标使用同一色系。

## 使用步骤

1. 点击上传区或拖入 **一张** JPEG、PNG、WebP（最大 20 MB）。暂不支持 HEIC；需先转换。不支持动画图片，解码像素上限为 8000 万。服务端读取实际格式并验证解码，不依据文件扩展名或 MIME 判断。
2. 含有效 EXIF GPS：读取 WGS84 原始位置，调用 `AMap.convertFrom(..., 'gps', ...)` 得到地图 GCJ-02 位置。转换失败可重试或手动选点。
3. 无 GPS、无效 GPS 或元数据无法解析：在地图点击选点。自动定位后点击地图修正，也标记为“手动定位”。手动坐标不再次转换。
4. 可写最多 200 字备注，检查地图位置，勾选“我已确认地图上的位置”，再点击保存。
5. 保存成功后更新照片卡片和地图标记。失败时保留照片、位置、勾选与备注，可重试。每张临时照片只能产生一条记录，重复请求返回已有记录。
6. 点击历史卡片或地图标记选中记录，查看照片、拍摄时间、打卡时间及坐标。查看历史时返回当前照片位置后才能确认新照片。
7. 删除前须在弹窗确认，随后同时删除记录及对应照片。

拍摄时间没有时显示“未知”；EXIF 无时区时保留本地时间文本，标记“时区未知”，不虚构 UTC 偏移，也不使用上传时间代替。打卡时间另按实际保存时间记录。

## 本地数据与恢复

默认目录 `data/`（忽略 Git）：

- `checkins.sqlite`：SQLite 数据库，WAL 模式。
- `tmp/`：上传成功、尚未保存的原始照片。
- `photos/`：保存后的原始照片。
- `trash/`：删除过程的中转文件，用于数据库失败或进程中断恢复。

配置 `DATA_DIR` 可改变目录；相对路径以项目为基准。自定义目录需额外添加忽略规则。照片保留原始文件，不把二进制写入数据库。备份时停止服务后复制整个数据目录，不仅复制单个数据库文件。

保存时在事务内移动文件并插入记录；失败回移文件。删除时先移动到中转目录，数据库删除失败则恢复照片。启动时恢复中断的移动、清理已删除的中转文件。启动及每小时清理超过 24 小时的未保存照片。清理只操作应用管理的文件名及目录，拒绝目录或文件符号链接。

### 数据库结构（schema v1）

首次运行创建表，不删除已有数据库。`PRAGMA user_version=1`；当前没有旧版本数据迁移。今后结构变更需提供迁移并保留数据。

| 表 | 字段与说明 |
| --- | --- |
| `uploads` | `id` 临时标识、`filename` 管理文件名、`metadata` 服务端 EXIF JSON、`created_at` 上传时间 |
| `records` | `id` 记录标识、`upload_id` 唯一约束、`filename` 照片文件名、`note` 备注 |
| 原始坐标 | `original_lng`、`original_lat`、`original_system`（照片 GPS 为 WGS84；无 GPS 的手动位置为 GCJ-02） |
| 地图坐标 | `map_lng`、`map_lat`（GCJ-02） |
| 定位来源 | `location_source`：`exif` 或 `manual` |
| 时间 | `captured_at`、`captured_timezone`、`captured_at_raw`、`checked_in_at` |

含 GPS 照片即使手动修正，也保留照片原始 WGS84 坐标，同时存储修正后的地图坐标。数据库按打卡时间倒序查询。

## 接口

| 方法与路径 | 作用 |
| --- | --- |
| `GET /api/health` | 本地服务状态 |
| `GET /api/config` | 地图是否配置、公开 Key、大小限制；不返回安全密钥 |
| `GET /api/setup-guide` | 中文地图配置步骤 |
| `POST /api/uploads` | multipart 单字段 `photo`，校验、临时保存与解析 |
| `POST /api/records` | JSON：`uploadId`、`note`、`locationSource`、`position`（`lng`、`lat`、`coordinateSystem: "GCJ-02"`） |
| `GET /api/records` | 倒序读取记录与照片 URL |
| `DELETE /api/records/:id` | 删除记录及照片；重复删除安全返回 204 |
| `GET /media/:folder/:filename` | 读取已登记的临时或正式照片 |
| `GET /_AMapService/*` | 固定高德服务代理 |

前后端均限制尺寸、备注、坐标范围与定位来源。原始坐标及拍摄时间取自服务端元数据。API 拒绝非本机 Host 与非本机来源。不提供账号认证，适用于本机单人使用。

兼容浏览器可通过 WebMCP 工具 `list_photo_checkins` 读取当前记录、`show_photo_checkin` 选中已有记录；普通浏览器自动跳过。该浏览器提案能力不影响常规操作；已读取到工具注册信息，工具调用因执行 API 兼容差异尚未验收。

## Git 与文档

本目录为独立本地 Git 仓库（main），首次提交名称为“首次提交”；未配置远程仓库，未改动上层知识库的 Git 配置及暂存区。`.gitignore` 保留已有规则，忽略密钥、本地环境、数据库、照片、依赖、构建和日志。提交前用 `git status --short` 与 `git check-ignore -v <路径>` 检查。

源码可修改后用 `npm run dev` 调试；交付保持本地版，无公开部署或云端照片存储。功能计划见 `照片打卡网页MVP开发计划.md`，协作约定见 `AGENTS.md`，变更与验证边界见 `CHANGELOG.md`。
